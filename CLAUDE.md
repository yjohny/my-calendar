# TextCal - Development Guide

## Project Overview
A text-based iOS calendar app (Swift/SwiftUI, iOS 17+) that lets users type events in natural text format. Events sync bidirectionally with Apple EventKit; journal/freeform text is stored as per-day files.

## Build & Run
```bash
swift build          # Build the project
swift test           # Run tests
```
Xcode project: `TextCal.xcodeproj`

## Architecture
- **Models/CalendarStore.swift** — Main `@Observable` store. Manages `dayTexts` (full interleaved text per date — events and journal mixed in user's order) and `eventColorMap` (calendar colors from EventKit keyed by title+time). Parses user text, syncs events to EventKit, stores full text to file preserving layout order. Events and journal text can be freely interleaved. Exposes `syncStatus` (`.idle`, `.saving`, `.syncing`, `.error(String)`) for UI feedback. Includes an LRU cache (max 180 entries) that evicts old `dayTexts` entries and reloads from disk on demand. Caches parsed event keys per date to avoid re-parsing unchanged text.
- **ViewModels/CalendarViewModel.swift** — Manages the scrollable date range (±90 days, expands on demand). Caches the `dates` array and rebuilds it only when `startDate`/`endDate` change. Exposes `dateRangeStart`/`dateRangeEnd` for the scrubber.
- **Parsing/** — `LineParser` parses lines into `.event`, `.allDay`, `.eventNote`, `.journal`, `.blank`. `TimePatterns` has regex for time formats and recurrence markers.
- **Persistence/** — `EventKitManager` (actor) wraps EKEventStore CRUD; `saveEvent()` and removal methods throw on failure. `EventKitSync` converts between text lines and `EKEvent` objects; uses a static cached `DateFormatter` for time rendering. `FileStore` (actor) handles per-day text files. `ChangeCoalescer` debounces saves per-date, tracks pending save closures in `pendingSaves`, and reports errors via an `onError` callback. Its `flush()` method cancels debounce timers and executes all pending saves immediately (used during app shutdown).
- **Views/** — SwiftUI views. The main view is a continuous-document layout: days flow together without dividers, with date headers styled as inline uppercase headings. `DayTextEditor` uses an always-editable `SyntaxHighlightingTextView` (a `UIViewRepresentable` wrapping `UITextView`) with inline syntax coloring — no edit/display mode switch. `StyledTextView` is retained for read-only contexts (search results). `NavigationStack` with bottom toolbar for Today/Search/Events Only filter/Calendars/Help. `DateScrubber` on right edge. `SearchView` provides cross-day search. All views include VoiceOver labels and reduce-motion support.
- **Utilities/Strings.swift** — Centralized `LocalizedStringKey` constants for all user-facing strings (localization-ready).
- **Supporting/PrivacyInfo.xcprivacy** — Apple-required privacy manifest. Declares UserDefaults usage (`CA92.1` — app-only settings for `CalendarSettings` and `@AppStorage`). No tracking, no collected data types, no tracking domains. Must be kept in the Resources build phase.

## Key Patterns
- Uses rounded (SF Rounded) fonts throughout for a softer, modern feel. Monospaced is used only for time portions in event lines (e.g., `9:00 AM`) to maintain clean tabular alignment. Parsed event titles use medium weight to visually distinguish them from regular journal text.
- Event format: `9:00 AM - Title`, `9:00-10:30 AM - Title`, `9:00-10:30 - Title` (24h), `14:00 - Title`, `* All Day Event`. AM/PM is optional; without it, hours are interpreted as 24-hour format.
- Recurrence: `(daily)`, `(every weekday)`, `(every Monday)`, `(monthly 15th)`, `(yearly)`
- Recurring events from EventKit are treated as read-only occurrences during sync — only non-recurring TextCal events are removed and recreated on edit to avoid duplication
- **Multiple calendars**: Read-all, write-to-default model. `EventKitManager.events(for:)` fetches from all calendars (`calendars: nil`). The user picks a default calendar via `CalendarSettings` (stored in UserDefaults); new events go there. The `[CalendarName]` suffix syntax (e.g., `9:00 AM - Meeting [Work]`) overrides the default for individual events. The legacy prefix syntax (e.g., `[Work] 9:00 AM - Meeting`) is still supported for backward compatibility. Default-calendar events are deleted and recreated on each sync; override-calendar events are create-only (matched by title, start time, and end time to avoid duplicates). The "TextCal" calendar is the fallback if no default is set.
- **Calendar colors**: `StyledTextView` uses `EventColorKey` (title+time→Color map built from EventKit) to look up calendar colors for event lines. Colors are adjusted for contrast against the current color scheme (light/dark mode) via `ensureContrast()`. Events from non-default calendars show a subtle calendar name label in caption2 size with tertiary opacity (0.6) to minimize visual clutter on busy days.
- **Interleaved text**: The per-day file stores the full text as the user typed it — events and journal text mixed in any order. Events are parsed out for EventKit sync but the layout order is preserved. EventKit-only events (added from other apps) are automatically adopted into the editable text on first load via `DayTextEditor.adoptUnmatchedEvents()`, making them fully editable. Adoption is tracked per-session by `adoptedUnmatchedKeys` to prevent re-insertion.

## Known Patterns to Watch
- **Calendar name suffix vs prefix**: `LineParser.parse()` checks for a `[CalendarName]` suffix first (new format: `9:00 AM - Meeting [Work]`), then falls back to prefix (legacy: `[Work] 9:00 AM - Meeting`). `EventKitSync.textLine(from:defaultCalendarId:)` renders the suffix format. `StyledTextView.stripCalendarPrefix()` strips both formats for display. Both formats must be kept in sync across these three files.
- **Recurring event sync**: `syncEventsToEventKit` skips parsed events that match existing recurring occurrences (by title, start time, end time, and all-day status). Non-recurring events are deleted and recreated. Be careful not to break this deduplication logic.
- **Recurrence round-tripping**: "Every weekday" is stored in EventKit as a `.weekly` rule with 5 `daysOfTheWeek` (Mon-Fri), not as `.daily`. `EventKitSync.recurrenceText()` must detect this pattern under the `.weekly` case to render it back as `(every weekday)`.
- **EKWeekday raw values**: When building collections of `EKWeekday.rawValue` (Int), always fully qualify each enum case (e.g., `EKWeekday.monday.rawValue, EKWeekday.tuesday.rawValue`). Swift infers shorthand like `.tuesday.rawValue` as members of `Int` rather than `EKWeekday`, causing build errors.
- **Time validation**: `TimePatterns.parseTime()` validates hours (0-23) and minutes (0-59), returning `nil` for out-of-range values. AM/PM is optional in both `eventLinePattern` and `timeRangeEventPattern`; without it, hours are used as-is (24-hour format).
- **Inline parse feedback**: Both `SyntaxHighlightingTextView` and `StyledTextView` provide visual warnings (orange color) for: (1) unrecognized recurrence patterns — parenthesized text at the end of an event title that looks like a recurrence attempt (starts with "every", "daily", "weekly", etc.) but failed `parseRecurrence()`; detected via `TimePatterns.looksLikeRecurrence()`. (2) Unknown calendar names — `[CalendarName]` syntax where the name doesn't match any EventKit calendar (case-insensitive). Both views accept a `calendarNames: [String]` parameter for validation.
- **All-day events**: EventKit requires all-day event `endDate` to be the start of the *next* day, not the same day as `startDate`.
- **Always-editable editor**: `DayTextEditor` no longer toggles between modes. It uses `SyntaxHighlightingTextView` (a `UIViewRepresentable` wrapping `UITextView`) that applies inline syntax highlighting via `NSTextStorage` attributes — colored monospaced time text, rounded fonts, italic tertiary colors for notes (to distinguish from journal text), faded recurring events. The placeholder is a `UILabel` overlay shown only when text is empty.
- **Events-only filter**: A toggle button (filter icon, `Cmd+E`) in the bottom toolbar sets `eventsOnly` on the main view. When active, `DayTextEditor` switches from the editable `SyntaxHighlightingTextView` to a read-only `StyledTextView` that only renders event lines (all-day and timed), completely collapsing journal text, notes, and blank lines. This prevents accidental editing of invisible text.
- **DayTextEditor refresh**: Uses a cancellable `refreshTask` to prevent stale async results from overwriting current state when the user scrolls quickly between dates. Calls `CalendarStore.ensureLoaded(for:)` to load text from disk on cache miss before displaying. `DaySectionView.onAppear` prefetches EventKit data for adjacent days (±1, +2) via `refreshEventsInRange()` so colors are ready before the user scrolls there.
- **EventKit batch queries**: `CalendarStore.refreshEventsInRange(from:to:)` loads events for a date range in a single `EKEventStore` query and groups them by day, instead of issuing one query per date. The shared `processEventsForDate()` method handles color map + unmatched event logic for both single-date and batch paths.
- **Debounced EventKit sync**: `CalendarStore.update()` debounces EventKit sync (800ms) via a cancellable `syncTask` so typing doesn't trigger a delete-and-recreate cycle on every keystroke. File saves are separately debounced (500ms) via `ChangeCoalescer`, which tracks pending saves per-date so concurrent edits to different days don't cancel each other.
- **App lifecycle & shutdown safety**: `CalendarStore.forceSave()` cancels the debounce sleep of any in-flight `syncTask` but then `await`s its `.value` to completion — never fire-and-forget cancel. This ensures an in-progress EventKit sync runs to completion before the app is suspended (Task cancellation only interrupts `Task.sleep`, not EventKit ops, so awaiting is required to avoid suspension mid-sync). It then flushes the `ChangeCoalescer` (executing all pending debounced saves immediately) and writes all cached `dayTexts` to disk. Triggered from three layers: (1) `TextCalApp` monitors `scenePhase` and calls `forceSave()` on `.background`, (2) `CalendarDocumentView` observes `willResignActiveNotification`, `didEnterBackgroundNotification`, and `willTerminateNotification` via `NotificationCenter`. All three layers exist for comprehensive coverage since iOS may skip some notifications depending on how the app is suspended or terminated.
- **Create-before-delete sync (crash safety)**: `EventSyncCoordinator.syncEvents()` uses a three-phase flow for the default calendar: (1) snapshot existing events (recurring and non-recurring separately), (2) create all new events, (3) delete only the *specifically snapshotted* non-recurring events via `EventKitManager.removeSpecificEvents([EKEvent])`. A crash between phases 2 and 3 leaves temporary duplicates (self-healing on next sync) instead of permanent deletions. **Never change this order** and never use `removeManagedEvents()` in the sync path — deleting by date-range lookup could remove freshly-created events if titles/times coincide. Step 3's `removeSpecificEvents` guarantees we only delete the exact pre-captured events.
- **Sync verification**: After the create/delete phases, `syncEvents()` re-fetches events and compares the final non-recurring count against `expectedNewEventCount`. A mismatch throws `SyncError.verificationFailed(expected:actual:)` which flows into the error banner + retry UI. This catches silent EventKit failures (dropped saves, race with external edits).
- **Passive duplicate cleanup**: `CalendarStore.refreshEventsInRange()` opportunistically runs `EventKitManager.removeDuplicateEvents()` on the default calendar when it detects exact duplicates (same title, start, end, isAllDay) among non-recurring events. This self-heals any duplicates left by previously-crashed syncs, even on days the user never edits again. The cleanup only touches the default calendar — never override calendars. If cleanup runs, events are re-fetched before `processEventsForDate()` so downstream state reflects the cleaned reality. The first duplicate (by startDate, then eventIdentifier) is kept for deterministic ordering.
- **EventKit batch commits**: `removeManagedEvents()`, `removeSpecificEvents()`, and `removeDuplicateEvents()` all batch their deletions into a single `store.commit()` call instead of committing per-event, improving sync performance on days with many events.
- **Biweekly recurrence**: Uses elapsed days (`days / 7`) to compute week offset, not `.weekOfYear` (which is an ISO week number and breaks across year boundaries).
- **Single-pass parsing**: `CalendarStore.update()` extracts journal lines and event groups in a single loop over the text lines, avoiding a redundant second pass.
- **DateScrubber caching**: Month tick positions are computed as normalized progress values (0…1) and stored in `@State`; they're recomputed via `.onChange(of:)` when `startDate`/`endDate` change. The `DateFormatter` for the floating label is a static cached instance. Haptic feedback (light impact) fires when dragging across month boundaries.
- **StyledTextView**: Pre-parses text lines into a `ParsedLine` enum (computed property) to avoid re-parsing on every SwiftUI render. Uses concatenated `Text` views (not `HStack`) so long event names wrap to the next line naturally. Line spacing is 7pt. Event notes render in italic with tertiary color to visually distinguish them from journal text. Applies `ensureContrast()` to EventKit calendar colors — brightens dark colors in dark mode (blends toward white) and darkens light colors in light mode (scales down RGB).
- **Toolbar**: Today, Search, Calendars, and Help are in a standard iOS bottom toolbar (`NavigationStack` + `ToolbarItemGroup(.bottomBar)`). A sync status indicator (spinner + "Saving..."/"Syncing...") appears in the navigation bar's principal slot during persistence operations. Errors show as a red warning with auto-dismiss (5s) or tap-to-dismiss.
- **Keyboard shortcuts**: Cmd+F (search), Cmd+T (today), Cmd+/ (help) via `.keyboardShortcut()` on toolbar buttons. Arrow keys (up/down) navigate between days via `.onKeyPress()` + `.focusable()`.
- **Date header affordance**: `DateHeaderView` is styled as an inline document heading — uppercase subheadline in secondary color (accent color for today), with "Today" shown as inline text rather than a pill badge. A subtle chevron appears when `onTap` is set, hinting that headers are tappable to open the date picker. No dividers between days; the layout feels like one continuous text document. Generous spacing (28pt top, 8pt bottom) gives each day breathing room.
- **Search**: `SearchView` searches `CalendarStore.searchDayTexts(query:)` across all in-memory `dayTexts`. Debounced 300ms via `.task(id:)`. Results capped at 50 (most recent first) to prevent UI lag with large datasets. Results grouped by date with query text highlighted. Tapping a result dismisses the sheet and calls `viewModel.jumpTo(date:)`.
- **Default event duration**: Events without an explicit end time default to 1 hour in `EventKitManager.saveEvent()`. `EventKitSync.timedLine()` detects this default (duration == 3600s) and hides the end time when rendering back to text, preserving the user's original format.
- **SwiftUI List with non-Identifiable types**: When using `EKCalendar` or other non-`Identifiable` EventKit types in a `List`, use `List { ForEach(items, id: \.keyPath) { ... } }` instead of `List(items, id: \.keyPath) { ... }`. The direct `List` initializer fails to infer generic parameters for these types, causing cascading build errors. Additionally, always fully qualify the key path root type *and* the closure parameter type in `ForEach` (e.g., `ForEach(calendars, id: \EKCalendar.calendarIdentifier) { (calendar: EKCalendar) in`), otherwise Swift cannot infer the generic parameters and produces cascading type errors.
- **Error propagation**: `ChangeCoalescer` reports save errors via its `onError` callback. `EventKitManager.saveEvent()`, `removeEvent()`, `removeManagedEvents()`, `removeSpecificEvents()`, and `removeDuplicateEvents()` all throw on failure. `EventSyncCoordinator.syncEvents()` throws `SyncError.verificationFailed` on post-sync count mismatches. `CalendarStore` catches these and sets `syncStatus = .error(...)` for the UI to display. Never silently swallow save/sync errors with `try?` — the only exception is the passive duplicate cleanup in `refreshEventsInRange()`, which uses `try?` because it's a best-effort background sweep that shouldn't block loading.
- **LRU cache**: `CalendarStore` tracks date access order and evicts entries beyond 180 days. On cache miss, callers should use `ensureLoaded(for:)` to async-load from `FileStore` before reading `dayTexts`. When adding LRU eviction, also evict `eventColorMap`, `unmatchedEventLines`, `journals`, and `parsedKeyCache` entries for the evicted date.
- **Parsed key caching**: `processEventsForDate()` caches the set of `EventColorKey` values parsed from user text, keyed by `(date, textHash)`. If the text hasn't changed, it reuses the cached keys instead of re-parsing every line.
- **Permission denied banner**: `CalendarDocumentView` shows a dismissable banner when `hasCalendarAccess == false`, with a link to Settings. Dismissal is persisted via `@AppStorage("dismissedCalendarPermissionBanner")`.
- **Accessibility**: All interactive views have VoiceOver labels and hints. `DateScrubber` and `CalendarDocumentView` respect `@Environment(\.accessibilityReduceMotion)` to skip animations. `CalendarPickerView` uses `@ScaledMetric` for the color dot size to support Dynamic Type. When adding new views, always include `.accessibilityLabel()` and `.accessibilityHint()` where appropriate.
- **Localization**: All user-facing strings are centralized in `Utilities/Strings.swift` as `LocalizedStringKey` constants. When adding new strings, add them to `Strings` rather than hardcoding in views.

- **Search: EventKit events** — `SearchView` searches both `dayTexts` and EventKit events (from other apps) via `CalendarStore.searchEventKitEvents()`. EventKit results appear in a separate "From Other Apps" section below user text matches.
- **Calendar visibility toggles** — `CalendarPickerView` now has a "Visibility" section where users can toggle calendars on/off. Hidden calendar identifiers are persisted in `CalendarSettings.hiddenCalendarIdentifiers` (UserDefaults). `EventKitManager.events(for:excludingCalendars:)` filters them out.
- **Conflict & overlap warnings** — `detectConflicts(in:)` (free function in CalendarStore.swift) compares parsed event time ranges and returns conflicting titles. `StyledTextView` shows a warning indicator on overlapping events.
- **Faded recurring events** — `StyledTextView` applies `.opacity(0.7)` to recurring event lines (those with a recurrence rule), matching what `SyntaxHelpView` documents.
- **Sync error recovery** — Error banners in the toolbar no longer auto-dismiss after 5 seconds. Instead they show a "Retry" button (calls `CalendarStore.retryLastSync()`) and a dismiss "X" button. The last failed sync date is tracked for retry.
- **Adopted EventKit events** — Events from other apps are automatically adopted into the editable text (no separate read-only section). Once adopted, they behave like any user-typed event and sync normally via EventKit.
- **Markdown journal text** — Journal lines are rendered via `AttributedString(markdown:)` with `.inlineOnlyPreservingWhitespace`, supporting **bold**, *italic*, ~~strikethrough~~ etc. Raw text is preserved in files.
- **Alarm/reminder syntax** — `(!15m)`, `(!1h)`, `(!0m)` at end of event titles set `EKAlarm` on the event during sync. Parsed by `LineParser.extractAlarm()` / `TimePatterns.parseAlarm()`. Documented in `SyntaxHelpView`.
- **Event templates** — `TemplateStore` (actor) persists reusable text snippets as JSON (`textcal/templates.json`) in a versioned envelope `{version, templates}`. `TemplatePickerView` shows saved templates for one-tap insertion. Accessible from the keyboard toolbar in `DayTextEditor` via clipboard icon. Templates can be created, edited, and deleted with swipe actions.
- **Inline autocomplete** — `AutocompleteEngine` detects trigger characters in the current line: `[` suggests calendar names from EventKit, `(` suggests recurrence patterns, digits at line start suggest times in 15-minute increments. Suggestions appear as a horizontal chip bar (`AutocompleteSuggestionsView`) above the text editor. Selecting a suggestion replaces the trigger text.
- **Undo/redo preservation** — Since the editor is always-editable (no mode transitions), the `UITextView`'s built-in undo manager is preserved naturally. Text is only overwritten from the store on initial load when the local text is empty.
- **Week summary view** — `WeekSummaryView` is a text-native week overview showing 7 days as a compact list (Mon–Sun) with condensed event summaries. Each day shows event count, first few titles, and unmatched event count. Navigate weeks with chevron buttons. Tap a day to jump to it. Accessible via Cmd+W or the nav bar week button. Intentionally text-flavored, not a graphical grid.
- **Move event between days** — Long-press an event line in `StyledTextView` to get a context menu: "Move to Tomorrow" (instant) or "Move to Date..." (date picker). `CalendarStore.moveEventLine()` removes the line from the source day's text and appends it to the target day, then syncs both days to EventKit. This is the text-native equivalent of drag-and-drop — a shortcut for cut/navigate/paste.
- **Persistence schema versioning** — All three persistence surfaces carry explicit version markers so future releases can migrate forward:
  - **FileStore**: Writes `textcal/schema.json` (`{version, format, writtenBy}`) on first save. `readSchemaVersion()` returns `nil` for legacy installs. Per-day `.txt` files are kept as plain text (no embedded header) so users can open/edit them in Files.app. Current version: `FileStore.currentSchemaVersion = 1` (`per-day-txt`). To change the file layout, bump the version and add a migration branch on load.
  - **TemplateStore**: Wraps templates in a versioned envelope (`TemplateFile {version, templates}`). `load()` tries the current envelope first, then falls back to decoding the legacy bare-array format for backward compatibility. Current version: `TemplateStore.currentVersion = 2`.
  - **CalendarSettings**: Writes a `settingsSchemaVersion` key to UserDefaults and runs `migrateIfNeeded()` on init. An unset value is treated as version 0. Future per-version migration branches go inside `migrateIfNeeded()` before the version marker is bumped.
- **Data export** — `CalendarStore.exportAllDataAsText()` reads all journal files via `FileStore.loadAllJournals()` (so LRU-evicted days are included) and serializes them via `DocumentSerializer.serialize()`. `CalendarPickerView` exposes an "Export All Data" button in a "Data" section — the button kicks off the async export and then swaps itself for a `ShareLink` once the text is ready. The picker takes an optional `store: CalendarStore?` parameter; the export section is hidden if it's nil.

## App Store & Release
- **Bundle ID**: `com.textcal.app`, **Version**: `MARKETING_VERSION` in project.pbxproj, **Build**: `CURRENT_PROJECT_VERSION`.
- **Privacy manifest**: `Supporting/PrivacyInfo.xcprivacy` declares UserDefaults usage (reason `CA92.1`). If new required-reason APIs are added (e.g., file timestamp, disk space, active keyboard), update this manifest. See Apple's "Describing use of required reason API" documentation.
- **App icon**: `Supporting/Assets.xcassets/AppIcon.appiconset/AppIcon.png` — 1024x1024 universal icon. Dark background with color-coded event lines, monospaced times, and a text cursor. `Contents.json` references it with `"filename": "AppIcon.png"`.
- **Privacy**: App is fully on-device — no network calls, no analytics, no third-party SDKs. Only system frameworks (EventKit, SwiftUI, UIKit). Calendar access declared via `NSCalendarsFullAccessUsageDescription` in Info.plist.
- **Localization**: Architecture is ready (`Strings.swift` with `LocalizedStringKey` constants) but currently English-only. To add languages, create `.lproj` directories with `Localizable.strings` files.
- **No entitlements file needed**: App uses only standard capabilities (Calendar access, local file storage, UserDefaults).
